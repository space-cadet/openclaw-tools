# T16: Token-Usage Parser — 9.x Version Awareness + SQLite Migration Fix

*Created: 2026-09-18*
*Status*: ✅ COMPLETE

## Problem

The nightly token report returned **0 tokens** after the OpenClaw 9.x upgrade despite heavy usage. Three separate bugs compounded:

1. **Version detection stale** — Parser read the old Node v22 `package.json` (2026.6.34) instead of the running Node v24.21.0 install (2026.9.4). Pre-9.x logic then **ignored the SQLite backend** where all live data lives.

2. **macOS SQLite URI failure** — `sqlite3.connect("file:{snap}?mode=ro", uri=True)` fails on temp files on macOS. The snapshot was created successfully but could not be opened.

3. **Timestamp format mismatch** — SQLite stores UTC timestamps with `Z` suffix (e.g., `2026-09-18T15:06:59.778Z`), but `--since`/`--until` boundaries are local IST without suffix. String comparison `"2026-09-18T15:06:59.778Z" < "2026-09-18T00:00:00"` is always False, so all events were filtered out.

## Root Cause

OpenClaw 9.x moved live session transcripts from loose `.jsonl` files into `openclaw-agent.sqlite` (`transcript_events.event_json`). The parser from T15 already handled `.jsonl.deleted.*.zst` archives, but had no SQLite reader and no version detection to know it *should* read SQLite.

## Fix Applied

**`parse.py` — five changes:**

1. **`_detect_openclaw_version()`** — scans all NVM node trees, collects every `openclaw/package.json` version, returns `max()`. Never shells out to `openclaw --version` (can block on gateway lock).

2. **`detect_storage_backends()`** — reads version, classifies storage as `jsonl` | `sqlite` | `mixed` | `unknown`. Emits warnings when version/storage combination is anomalous (e.g., pre-9.x version with SQLite DB present).

3. **`_normalise_ts(ts)`** — strips `Z` suffix from SQLite timestamps so string comparison with local `since`/`until` works.

4. **`sqlite3.connect(snap)`** — replaced URI mode with plain connect. macOS sqlite3 refuses URI read-only mode on temp files.

5. **`find_sessions(since=...)`** — added mtime pre-filter so `--today` skips 5,600+ stale JSONL files. Only opens files modified within the time window.

**Version-aware behavior:**

| Version | Storage | Behavior |
|---------|---------|----------|
| pre-9.x (≤2026.6.x) | JSONL only | Reads `.jsonl`/`.jsonl.gz`, warns if SQLite DB found |
| 9.x (≥2026.9.x) | SQLite primary | Reads `transcript_events`, merges with any JSONL |
| unknown | auto-detect | Reads whatever is present, warns |
| transitional | mixed | Reads both, warns |

**Report header now shows:**
```
OpenClaw version : 2026.9.4
Storage backend  : mixed  (jsonl=5581, sqlite=1, zst_archives=22)
⚠️  Mixed storage: SQLite (9.x live) + loose JSONL files detected.
```

JSON output includes `openclaw_version`, `storage_backend`, `storage_counts`, and `warnings` fields.
