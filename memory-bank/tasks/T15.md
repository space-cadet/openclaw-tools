# T15: Token-Usage Parser — zstd support + Codex/interactive split

*Created: 2026-09-16*
*Status*: ✅ COMPLETE

## Problem

Two bugs in the token-usage nightly report caused false reports:

1. **"No logged LLM activity since Aug 16"** — Parser only globbed `*.jsonl` + `*.jsonl.gz`. Post-9.4-upgrade sessions were zstd-compressed as `.jsonl.deleted.2026-09-1*.zst`, so Sept 15–16 activity was invisible.

2. **"12M Luna tokens yesterday"** — Codex rollout logs (background agent jobs using GPT-5.6-Luna) were merged into the user-facing report. User's actual interactive model was k2.7.

## Root Cause

`common.py:find_sessions()` globbed only `*.jsonl` and `*.jsonl.gz`.
`ingest.py:classify_session()` did not detect Codex rollout paths and assigned them `user` job_type.

## Fix Applied

**`common.py`:**
- Added `*.jsonl.*.zst` to `find_sessions()` glob
- Added `_zstd_open()` helper (subprocess `zstd -dc` wrapped in TextIOWrapper)
- `parse_session()` dispatches to `_zstd_open` / `gzip.open` / `open` by extension
- Applied Cloudy's defensive fix: `(payload.get("info") or {}).get("last_token_usage")` — prevents `AttributeError` on `"info": null`

**`ingest.py`:**
- `classify_session()` returns `"background:codex"` for any path containing `codex-home/sessions`
- Added `.zst` opener to `classify_session()` content scan

## Verification

- 17 `.zst` sessions discovered and parsed (all `kimi/k2.7`, zero Luna)
- Full ingest: 5,598 files → `usage.db`
- Sept 14: 718K input k2.7; Sept 15: 260K input k2.7 — both now visible
- DB grouped totals confirm: `background:codex` = 1.02B Luna tokens (background), `user` = k2.7 only
